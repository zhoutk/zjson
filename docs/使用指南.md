## 1. 定位与快速开始

ZJSON 是**单文件、header-only、纯 C++17、零依赖**的 JSON 库：

- 整个库只有一个头文件 `src/zjson.hpp`，所有库符号都在一个命名空间 `ZJSON`（内部实现放 `ZJSON::detail`；另按标准要求为
  `std::tuple_size`/`std::tuple_element` 提供了特化，那是结构化绑定所必需）；
- 值类型语义（可拷贝、可移动、可作容器元素）；
- 吞吐（clang64 中位数，随数据集而异）：parse **114~173 MB/s**、stringify **363~537 MB/s**、copy **385~766 MB/s**
  （数据见 [`性能测试报告.md`](性能测试报告.md)），JSONTestSuite 全部通过。

快速开始：

```cpp
#include "zjson.hpp"   // 唯一需要的头文件

// 构造
ZJSON::Json doc{
    {"name", "kevin"},
    {"age", 10},
    {"scores", 95.98},
    {"tags", ZJSON::Json::array({1, 2, 3})},
};

// 序列化（紧凑单行）
std::string text = doc.toString();

// 解析（同时校验 UTF-8，等价大多数语言 json.loads 的严格度）
std::string err;
ZJSON::Json parsed = ZJSON::Json::ParseJsonStrictUtf8(text, err);
if (parsed.isError()) { /* err 里有失败原因 */ }

// 取值
int age = parsed["age"].toInt();
```

构建系统集成（CMake）：header-only 用 INTERFACE 目标即可——

```cmake
add_library(zjson INTERFACE)
target_include_directories(zjson INTERFACE <zjson.hpp 所在目录>)
if(UNIX)
    find_package(Threads REQUIRED)          # std::mutex 需要 pthread
    target_link_libraries(zjson INTERFACE Threads::Threads)
endif()
```

## 2. 构造 Json

```cpp
ZJSON::Json a;                        // 默认构造 = 空对象（JsonType::Object）！
ZJSON::Json arr(ZJSON::JsonType::Array);   // 空数组（Array 必须显式指定）
ZJSON::Json n = nullptr;              // null（必须送 nullptr，NULL 会被当成整数 0）
ZJSON::Json s = std::string("text");  // 字符串
ZJSON::Json i = 42;                   // 整数字面量 → int64 精确存储
ZJSON::Json d = 9.98;                 // 浮点 → double
ZJSON::Json b = true;                 // 布尔

// initializer_list 构造对象（explicit，需直接初始化），可任意嵌套
ZJSON::Json obj{
    {"fkey", false},
    {"okey", ZJSON::Json{{"math", 99}, {"str", "a string."}}},
};

// 数组请用 Json::array（Json{...} 花括号形式刻意留给对象，避免二义）
ZJSON::Json nums = ZJSON::Json::array({12, 13, 14});
```

要点：

- **`Json()` 默认是空对象**，不是 null 也不是 Error。想表示"空缺"请显式传
  `ZJSON::JsonType` 或检查 `getValueType()`；
- **整数按 `int64/uint64` 三态精确存储**：`{"id":9007199254740993}` 解析再序列化，
  数值原样往返（不经 double，`int64` 精度上限之上也不丢）。`42.0`、`42e0`、`-0`
  仍按 double 处理，用 `isIntegral()` 区分；
- 拷贝是**深拷贝**；`operator=` 是值语义。

## 3. 解析

| 接口 | 注释 | UTF-8 校验 | 重复键 | 备注 |
|---|---|---|---|---|
| `ParseJsonStrict(input, err)` | ✗ 拒绝 | ✗ | KeepLast | 严格 RFC 8259 |
| `ParseJsonStrictUtf8(input, err)` | ✗ 拒绝 | ✓ 拒绝 | KeepLast | **推荐默认** |
| `ParseJson(input, err)` | ✓ 允许 | ✗ | KeepLast | 宽松（容忍 `//`、`/* */` 注释） |
| `parse(input, err, options)` | 可配 | 可配 | 可配 | 全量定制 |
| `FromFile(path)` | — | — | KeepLast | 失败返回 Error Json |

全部返回 `Json`；失败时返回 **Error 哨兵**（`isError()` 为 true），原因写入 `err` 出参。

```cpp
std::string err;
ZJSON::Json doc = ZJSON::Json::ParseJsonStrictUtf8(input, err);
if (doc.isError()) {
    std::fprintf(stderr, "parse failed: %s\n", err.c_str());
}
```

`ParseOptions`（传给 `parse()`）：

```cpp
struct ParseOptions {
    bool allowComments = true;      // 是否容忍 // 与 /* */ 注释
    bool validateUtf8 = false;      // 是否拒绝非法 UTF-8 序列
    enum class DuplicateKeyPolicy { KeepFirst, KeepLast, Reject };
    DuplicateKeyPolicy duplicateKey = DuplicateKeyPolicy::KeepLast;
};
```

其他要点：

- **解析限深 101 层**；超出报错。通过 API 自建的深层文档（拷贝/打印/比较/销毁）
  已迭代化，不受此限；
- 末尾多余内容（trailing garbage）按失败处理；
- `ParseJson(std::string&&, ...)` 接管输入缓冲，**不复制文档文本**，大文档解析
  少一次全量拷贝；
- `FromFile` 一次性定长读入；文件不存在 / 无法打开返回 Error Json。

## 4. 序列化

```cpp
std::string compact = doc.toString();      // 紧凑单行
std::string pretty = doc.toString(4);      // 4 空格缩进美化
doc.dumpTo(std::ofstream("out.json"));     // 直接写流，不先拼整串（大文档推荐）
std::cout << doc;                          // operator<<（等价 dump）
```

- 字符串按 JSON 规范转义；数值按**最短往返**格式输出（解析回来的 double 与原文
  bit 级一致，RFC 8259 + IEEE-754）；
- 整数字面量原样写回（`9007199254740993` 不变成 `9007199254740992.0`）；
- **对象成员按插入序输出**（不是按键排序）——多次构造/重建会改变键序，做字节级
  比对或哈希前先想清楚键序是否重要；
- Error 节点 `toString()` 返回空串。

## 5. 读取值

### 5.1 `operator[]`：方便但有三个必须记住的语义

```cpp
ZJSON::Json v = doc["name"];       // 按 key 查（Object）
ZJSON::Json x = arr[0];            // 按下标查（Array）
ZJSON::Json deep = doc["a"]["b"];  // 链式访问
```

1. **返回副本**（容器成员深拷贝整棵子树）。要就地读写请用 `findPtr`/`findPtrAt`/
   `atRef`（返回引用/指针，不拷贝）；
2. **深搜回退**：键不是直系成员时，会**递归搜索整棵子树**，返回文档序第一个匹配
   （先序）。这很方便，但意味着 `"b"` 可能命中的是你不想要的嵌套层——
   只要直系语义时用第 8 节的 `directChild`/`hasChild`/`childValueOr`；
3. 查不到返回 **Error 哨兵**（`isError()` 为 true），后续 `toInt()` 等返回 0、
   `toString()` 返回空串——不会抛异常，但也**不会主动报错**，是否检查由你决定。

### 5.2 类型判定与转换

```cpp
bool isNull/isTrue/isFalse/isNumber/isIntegral/isString/isArray/isObject/isError();
int toInt();  int64_t toInt64();  uint64_t toUint64();
double toDouble();  float toFloat();  bool toBool();
std::string toString();               // String 节点返回值；其余节点返回**JSON 序列化文本**
std::vector<Json> toVector();         // Array → vector
std::string getValueType();           // 类型名字符串（7 种）
```

转换规则（与"其他库"不同的地方，容易踩）：

| 调用 | Number | true/false | String | 其他 |
|---|---|---|---|---|
| `toDouble()` | 数值 | 1 / 0 | **按前缀解析数字**（`"3.5abc"` → 3.5） | 0 |
| `toInt()` | 截断转 int | 1 / 0 | 同上再截断 | 0 |
| `toInt64()/toUint64()` | 整数节点**精确读**；double/String 走 C++ 转换 | 1 / 0 | C++ 转换 | 0 |
| `toBool()` | false | true/false | false | false |
| `toString()` | **JSON 文本**（如 `"42"`） | `"true"`/`"false"` | 字符串值 | 对象/数组为其 JSON 文本；Error 为空串 |

**没有"默认值"重载**：`toInt(3)` 这种写法不存在。要"缺失给默认"的语义，见第 8 节
的 `childValueOr`，或用下面的 `try_*`。

### 5.3 不抛异常的现代取值：try_get / try_int / try_double / try_string

```cpp
int port = 9090;
doc.try_get("port", port);                    // 成功才写入，失败保持原值

if (auto name = doc.try_string("name"))       // std::optional<std::string>
    use(*name);
std::optional<int> id = doc.try_int("id");
std::optional<double> score = doc.try_double("score");
```

`try_get` 支持：算术类型、`bool`、`std::string`，以及实现了 ADL `from_json` 的
自定义类型（扩展点，见 5.4）。

### 5.4 自定义类型映射（ADL 扩展点）

```cpp
struct Point { double x = 0, y = 0; };

void to_json(ZJSON::Json& j, const Point& p) { j.add("x", p.x).add("y", p.y); }
void from_json(const ZJSON::Json& j, Point& p) { p.x = j["x"].toDouble(); p.y = j["y"].toDouble(); }

Point p = doc.get<Point>();          // 取值
doc.add("center", center);           // 存值（自动走 to_json）
```

### 5.5 迭代与结构化绑定

```cpp
for (auto it = obj.cbegin(); it != obj.cend(); ++it) {
    std::string_view k = it->key();      // **string_view，非物化**
    const ZJSON::Json& v = it->value();
}

for (const auto& [key, value] : obj) {   // 结构化绑定（ADL get + tuple 协议）
    // key 是 string_view；刻意不提供 std::get<N>(entry)（向 std 加重载是 UB）
}
```

**`key()` 返回 `std::string_view`，且 `std::string` 从它拷贝初始化是 explicit**：

- ✅ `std::string k(e.key());`（直接初始化）
- ✅ `s += e.key();` / `v.emplace_back(e.key());` / 比较 / `.size()`
- ❌ `std::string k = e.key();`（拷贝初始化，编译失败）
- ❌ `take(e.key())`（形参按值 std::string）——加括号 `take(std::string(e.key()))`

需要持有副本时用 `ZJSON::ownedKey(e.key())`（返回 `std::string`，见第 8 节）。
视图只在文档存活期间有效。

## 6. 修改

```cpp
// Object：add 有两类重载（值 / key+值）；重复 add 同名键会留下重复成员！
obj.add("age", 11);
obj.add("child", subJson);            // 嵌套 Json 值

// Array
arr.push_back(v);  arr.push_front(v);  arr.insert(index, v);
arr.concat(otherArray);               // 数组拼接
obj.extend(otherObject);              // 对象合并

// 删除
obj.remove("key");                    // ⚠ 深搜：递归删除子树中**所有**同名键
arr.remove(index);                    // 数组按下标删
obj.take("key");                     // 取值 + 删除（同样是深搜；旧名 getAndRemove）
obj.clear();

// 指针写入（RFC 6901 寻址 + RFC 6902 "add" 语义；失败时文档不变）
doc.setAt("/servers/0/port", 8080);
doc.setAt("/servers/-", entry);       // "-" = 数组追加
```

三个危险区（本项目实战中真实踩过）：

1. **`operator=` 会把 `brother` 置空**。对数组元素赋值
   `arr[i] = v`（`operator[]` 返回的副本赋值本来也无效）或经引用赋值
   `it.value() = v`，都会**切断兄弟链、丢掉后面的元素**。数组元素替换用
   `ZJSON::setElement`（第 8 节）；
2. **`add()` 只追加**：对已存在的键再 add 会得到两个同名成员。替换语义用
   `ZJSON::setChild`；
3. **`remove(key)` / `take(key)` 深搜**：会递归动到子树里同名键。只要删直系成员时
   自己重建（参考第 8 节 `setChild` 的实现思路）。

## 7. JSON Pointer（RFC 6901）与 Merge Patch

```cpp
const ZJSON::Json* p  = doc.resolvePointerPtr("/a/b/0");  // 只读定位，nullptr = 不存在
const ZJSON::Json& r  = doc.atRef("/a/b");                // 引用（失败返回错哨兵）
ZJSON::Json* w        = doc.findPtrAt("/a/b");            // 可变指针（不存在 = nullptr）
ZJSON::Json* m        = doc.findPtr("key");               // 先直层、再深搜

doc.setAt("/a/b", value);                                 // 写入（见第 6 节）

// RFC 6902 JSON Patch
std::string err;
ZJSON::Json patched = doc.applyPatch(operations, err);

// RFC 7386 Merge Patch（就地生效）
doc.mergePatch(patch);
```

## 8. 直系子节点辅助块（强烈推荐使用的"安全方言"）

`zjson.hpp` 末尾内嵌了一组 `inline` 自由函数（`namespace ZJSON`），把本项目大型
迁移中沉淀的防坑语义集中成 8 个函数。**它们只依赖 public API**，行为由
`tests/test_util.cpp` 全量锁定。

### 直系读取（对应"QJsonObject 式"语义）

```cpp
// 1. directChild：只看直系子节点（不做深搜）。缺失/非对象 → nullptr
const ZJSON::Json* lat = ZJSON::directChild(point, "lat");

// 2. hasChild：直系成员是否存在
if (ZJSON::hasChild(cmd, "radius")) { ... }

// 3. childValueOr：直系取值，缺失给默认（Json() 默认为空对象）
double r   = ZJSON::childValueOr(cmd, "radius", ZJSON::Json(200.0)).toDouble();
ZJSON::Json v = ZJSON::childValueOr(obj, "maybe");   // 缺失 → 空对象

// 4. ownedKey：物化迭代器 key()（string_view → std::string）
std::string key = ZJSON::ownedKey(it->key());

// 5/6. memberCount / isEmptyObject：对象成员计数
// ⚠ size() 对 Object 返回 -1，isEmpty() 是 size()<=0 → **对任何对象恒为 true**
int  n = ZJSON::memberCount(obj);            // 非对象返回 0
if (ZJSON::isEmptyObject(obj)) { ... }       // 唯一正确的判空方式
```

### 安全变更

```cpp
// 7. setElement：数组元素替换（兄弟元素存活）。
//    ⚠ 不能写 array[index] = value（operator[] 返回副本），
//      也不能 it.value() = v（operator= 切断 brother 链）
ZJSON::setElement(arr, 1, ZJSON::Json("new"));

// 8. setChild：直系成员替换/新增（QJsonObject::insert 语义，保持成员顺序）。
//    ⚠ 不能 object[key] = value（副本赋值无效）；add() 只追加、同名留重复
ZJSON::setChild(obj, "mode", ZJSON::Json("fast"));
```

**ADL 注意**：这些函数带 `Json` 参数，会被参数关联命名空间（ZJSON）通过 ADL 找到。
如果你在自己的代码里也定义了**同名且带 Json 参数**的自由函数（如本地
`hasChild(const Json&, const std::string&)`），不加命名空间限定会导致重载二义。
要么改名、要么加限定（`ZJSON::hasChild`）。（不带 Json 参数的同名函数不受影响。）

## 9. 错误处理约定

ZJSON 全程**不抛 JSON 语义异常**，失败用 Error 哨兵表达：

- 解析失败 → `isError()`，原因在 `err` 出参；
- 查不到键/越界下标 → Error 节点，`toInt()` 等**返回 0**、`toString()` 返回空串；
- 推荐习惯：**边界处检查一次 `isError()`**（收到外部输入的入口、链式访问前判
  `isObject()`），内部信任类型；对"必须存在"的字段用 `try_get` 明确失败路径；
- `std::bad_alloc` 仍可能传播（内存耗尽）；const 读路径不分配、不抛（异常安全
  测试用替换全局 `operator new` 注入验证过）。

## 10. 线程与内存模型（摘要）

1. **节点池**：每线程 slab 池、永不释放 → "A 线程分配、B 线程释放（甚至 A 已退出）"
   天然安全且无锁；代价是**池驻留按线程累计、设计上不回收**——复用工作线程，
   不要"每请求一线程"（实测 64 个短命线程 ≈ 永久增长 440MB）；
2. **同一棵树并发只读安全**（惰性 key 索引 CAS 发布，const 读不写节点、不分配）；
   **并发读写同一棵树不安全**（与 `std::string` 相同），需外部加锁，且只有所有读
   都走值语义、没有引用/迭代器/`key()` 视图活过临界区时才成立。第 8 节里
   **`directChild` 返回的是指针**，属于「不能活过临界区」那一类（改名 `childValueOr` 的返回值版本）；
3. **跨 DLL/模块**：header 内联进每个模块，跨模块传递并在模块卸载后析构的文档
   不保证安全（本项目做法：zjson.hpp 全项目单副本 + 纯接口层隔离，供参考）；
4. LeakSanitizer 用户：池内存已标记为故意驻留（`__lsan_ignore_object` + `lsan.supp`）。

完整论述与反模式清单：[`多线程使用指南.md`](多线程使用指南.md)。

## 11. 性能要点

- **大文档**：优先 `ParseJson(std::string&&, ...)`（接管缓冲，少一次拷贝）与
  `dumpTo(ostream)`（流式写出，不先拼整串）；
- `toString()` 内部有 reserve 提示（解析过的文档按 arena 源长度预估），无需手动
  预留；
- 深拷贝/打印/比较均已迭代化，深文档（数万层 API 自建）不会栈溢出；
- 与 nlohmann/json、RapidJSON、simdjson 的对比数据：
  [`性能测试报告.md`](性能测试报告.md)。

## 13. 速查卡

```cpp
// ── 构造 ────────────────────────────────────────────────
ZJSON::Json obj;                          // 空对象
ZJSON::Json arr(ZJSON::JsonType::Array);  // 空数组
ZJSON::Json o{{"k", v}};                  // 对象初始化列表
ZJSON::Json a = ZJSON::Json::array({1,2});// 数组

// ── 解析 / 序列化 ──────────────────────────────────────
ZJSON::Json::ParseJsonStrictUtf8(s, err)  // 严格 + UTF-8（推荐）
ZJSON::Json::FromFile(path)               // 文件（失败 = Error）
doc.toString() / toString(4) / dumpTo(os)

// ── 读 ─────────────────────────────────────────────────
doc["k"] / arr[0]                         // 副本 + 深搜回退 + 缺失=Error
ZJSON::directChild(o,"k") / hasChild / childValueOr   // 直系语义（推荐）
doc.try_get("k", out) / try_int/try_double/try_string
ZJSON::memberCount(o) / isEmptyObject(o)  // 对象计数/判空（勿用 isEmpty）

// ── 写 ─────────────────────────────────────────────────
o.add("k", v)                             // 追加（重复键留重复成员！）
arr.push_back(v) / insert(i, v) / concat  // 数组
ZJSON::setChild(o, "k", v)                // 替换/新增（推荐）
ZJSON::setElement(a, i, v)                // 数组替换（推荐）
doc.setAt("/p/ath", v)                    // 指针写（RFC 6902 add）
```
